# M1 RAG 生产栈 Implementation Plan（发布 v0.9.0）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 落地 spec §7 全部内容——VectorStore 声明式 filter 能力接口、pgvector、redisvector、reranker 栈、高级 retrievers 四件，发 v0.9.0。

**Architecture:** filter 走可选能力接口（`SearchOptions` + `OptionSearcher`，沿 TextAdder/mmrSearcher type-assert 惯例，主接口零改动）；pgvector/redisvector 为 root module 新 partner（pgx v5 / go-redis v9 成为 root 直接依赖，与嵌套 checkpoint 模块 pin 对齐）；reranker 是 `DocumentCompressor` 抽象 + 两家 hosted API 实现；高级 retrievers 纯逻辑零新依赖。

**Tech Stack:** Go 1.26；新增依赖：`github.com/jackc/pgx/v5`（root）、`github.com/redis/go-redis/v9`、`github.com/cohere-ai`?（否——hosted rerank 走手写 REST，沿 chroma httptest 模式，不引 SDK）、Cohere/Jina 均手写 REST。

**Spec:** `docs/superpowers/specs/2026-09-16-parity-catchup-p0p1-design.md` §7（详细设计以 spec 为准，本文件只做派工拆分与验收）。

### Task A：filter 能力接口 + DSL + retriever 桥接 + in-memory/chroma 适配

**Files:** `core/vectorstores/`（SearchOptions/OptionSearcher/filter DSL 求值器 + in-memory 适配）、`core/retrievers/retriever.go`（searchKwargs 透传 filter）、`partners/chroma/`（服务端 filter 翻译到新接口）。

**要点（spec §7.1）：**
- `SearchOptions{K int, Filter map[string]any, ScoreThreshold float64, FetchK int}`（字段集以 spec 为准）+ 可选接口 `OptionSearcher`（`SimilaritySearchWithOptions` / `MMRSearchWithOptions`）
- 声明式 DSL 算子集：`$eq/$ne/$gt/$gte/$lt/$lte/$in/$nin/$between/$exists/$like`（langchain-pgvector 基线）；in-memory 客户端求值器 + 各 store 翻译
- retriever 桥接层透传 filter（现仅 k/fetch_k/lambda_mult/score_threshold）
- in-memory 与 chroma 适配新接口；chroma 已有 QueryOptions{Where,WhereDocument} → DSL 翻译
- 验收：DS L 求值器单测全算子；in-memory/chroma 既有测试零回归 + 新 filter 用例过 `standardtests.RunVectorStoreBasics` 扩展

### Task B：pgvector + redisvector + 依赖 pin 对齐检查

**Files:** `partners/pgvector/`、`partners/redisvector/`（新建）、`Makefile`（对齐检查目标）、`.github/workflows/ci.yml`（挂对齐检查）。

**要点（spec §7.2/7.3/§10 依赖策略）：**
- pgvector：pgx v5；collection≈表 + 自动 DDL（`vector(dim)` 列 + HNSW 索引）；距离 cosine/L2/IP；DSL→jsonb SQL；pgxmock 风格单测（或接口抽象）+ env-gated 真库 conformance
- redisvector：go-redis v9 + RediSearch（FT.CREATE vector 字段、FT.SEARCH KNN）；协议构造单测（miniredis 不支持向量查询）+ env-gated e2e（Redis Stack）
- root go.mod 的 pgx/go-redis 版本必须与嵌套 checkpoint 模块一致：`make check-dep-alignment`（脚本比对 root 与 langgraph/checkpoint/{postgres,redis} 的 require 行，不一致即失败），挂进 CI lint job 之后
- 验收：`standardtests.RunVectorStoreBasics` 对两家在 env-gated e2e 下全过；离线单测全过；对齐检查在 CI 生效

### Task C：reranker 栈 + 高级 retrievers 四件

**Files:** `core/retrievers/`（DocumentCompressor + ContextualCompressionRetriever + MultiQueryRetriever + ParentDocumentRetriever + EnsembleRetriever）、`partners/cohere/`、`partners/jina/`（hosted rerank，手写 REST）。

**要点（spec §7.4/7.5）：**
- `DocumentCompressor` 接口 + `ContextualCompressionRetriever`（retriever 命中→compressor 按 query 重排/压缩）
- Cohere Rerank API（POST /v2/rerank）与 Jina Rerank API（POST /v1/rerank）适配，httptest 假服务器测试
- MultiQueryRetriever：chat model 生成查询变体（可自定义 prompt，默认对齐 Python），并发检索去重合并
- ParentDocumentRetriever：child 切片检索、按 parent id 经 `core/stores.BaseStore` 回取全文
- EnsembleRetriever：多 retriever RRF 融合（rank_constant=60 对齐 Python）
- 验收：每件均有 Python-parity 行为测试；假服务器/conformance 全过；全仓回归
