# storm_storm

Go port of `examples/storm/storm.ipynb`.

## What the Go port demonstrates

The notebook's article-writing pipeline is rebuilt with the Go `StateGraph`
API as six nodes:

1. `init_research` - generate an outline and select editor personas;
2. `conduct_interviews` - run a nested interview graph once per editor;
3. `refine_outline` - fold interview insights back into the outline;
4. `index_references` - build a searchable document index;
5. `write_sections` - draft grounded sections with citations;
6. `write_article` - assemble the final Wikipedia-style article.

The nested interview graph uses `ask_question` <-> `answer_question` with an
`AddConditionalEdges` loop that stops after a fixed number of turns or when
the interviewer says thank you. The outer graph is compiled with a
`checkpoint.NewMemorySaver()` and invoked with a `ThreadID`.

## Offline safe substitution

The notebook uses OpenAI models, Wikipedia and DuckDuckGo search, LangSmith
hub prompts, OpenAI embeddings and a vector store. None of those are used
here:

- all "research" comes from a fixed in-memory slice of Wikipedia-style
  documents;
- outlines, editor personas, questions, answers, sections and the article are
  generated by deterministic Go string functions;
- the vector store is a sorted slice of reference URLs rendered as document
  blocks;
- no API key, network request, search engine, or embedding service is used.

## Run

```sh
cd examples/langgraph/storm_storm
go run .
```
