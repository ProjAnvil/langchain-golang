# Validation report

Date: 2026-11-18

Scope: all 86 standalone Go example modules under `examples/`:

- `examples/langchain/` — 8 modules
- `examples/deepagent/` — 1 module
- `examples/langgraph/` — 77 modules (4 native Go SDK examples + 73 Python notebook ports)

## Commands

```sh
./examples/validate.sh
```

For each module the script runs:

```sh
gofmt -w *.go
go mod tidy
go vet ./...
go build ./...
go run . >/dev/null
```

## Result

86/86 modules passed. The 73 Python ports are fully offline. `gemini-agent`
and `deepagent` print setup guidance and exit 0 when their provider keys are
absent; no module failed or hung without external credentials.

Each module contains:

- `go.mod` with its own module path and `replace github.com/projanvil/langchain-golang => ../../..`
- `main.go` using the Go SDK
- `README.md` with scope, source where applicable, and offline notes
- `go.sum` generated by `go mod tidy`

## Offline substitutions

The Python notebooks that used model providers, LangSmith, LangGraph Cloud,
MongoDB, Postgres, Redis, Pinecone, Cohere, local model downloads, SQL
execution, generated-code execution, or Playwright were ported with
deterministic in-memory equivalents. Graph topology, state channels,
checkpoint/resume, streaming, tool dispatch, and routing are preserved with
Go SDK APIs.

`go mod tidy` adds indirect requirements to modules importing core language
packages. These are required for `-mod=readonly` builds and were kept.
